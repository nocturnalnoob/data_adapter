# Detection Quality Adapter

Implementation of `instruction.md`'s Detection Quality Adapter, scoped to
**Part One §3 — rejecting false positives** — the portion of the assignment
that was asked for. False-negative recovery (§4, trajectory interpolation)
was explicitly called out as not expected ("intentionally much harder");
it's included as a separate, clearly-marked extension below the FP work,
not folded into the primary deliverable.

`REPORT.md` has the calibration/validation numbers. This file maps the
spec's clauses to the code that implements them.

## Repo layout

```
adapter/
  types.py            RawDetection, Candidate, Track, Detection, Status, RejectStage
  geometry.py          box math: IoU, overlap_ratio, aspect_ratio, centroid, diag
  io_clip.py            loads one clip bundle from downloads/<cid>/
  config.py              AdapterConfig (generic) + hands_config() (Part Two preset)
  reject_geometric.py     stages 1-3 (dedup, size, shape) + hand stereo-reach hook
  stereo.py                per-box disparity via rectified epipolar template matching
  association.py            tracking: position/motion only, no handedness label
  vio_utils.py                frame-indexed VIO speed / angular-rate access
  reject_temporal.py            stages 4-6 (displacement, unsupported, static)
  selection.py                   post-association cap-to-class_max by track support
  interpolate.py                  [beyond scope] gap-fill + leaving-frame test
  pipeline.py                      orchestrates the mandated stage order
  calibrate.py                      SS7: mines thresholds from the corpus
  validate.py                        SS8: precision/recall + interpolation-rate monitor
scripts/
  devset.py       ranks the 39 clips by bystander-frame density (dev-set selection)
  run_pipeline.py CLI: run the adapter over one/all clips -> hand_boxes_corrected.json
  visualize.py    draws before/after boxes on sampled frames, color-coded by status
adapter_out/      generated: calibrated_config.json, calibration_report.json,
                  validation_report.json, corrected/<cid>.json, viz/<cid>/*.png
REPORT.md         calibration + validation findings (the numbers)
```

## How to run

```
python -m adapter.calibrate           # writes adapter_out/calibrated_config.json
python scripts/run_pipeline.py --all  # writes adapter_out/corrected/<cid>.json
python -m adapter.validate            # writes adapter_out/validation_report.json
python scripts/visualize.py --clip 887c633e_t028 --n-frames 12 --show-rejected
```

`downloads/` (the 39-clip dataset) isn't in this repo — it's the ~3.7GB
source data, downloaded separately via the provided R2 bucket. Everything
under `adapter_out/` was generated by running the code above against it.

## Primary deliverable: rejecting false positives (§3)

### The six FP classes

| # | Class | Basis | Where |
| --- | --- | --- | --- |
| 1 | Duplicate detections | geometric | `reject_geometric._merge_duplicates` — union-find clustering by `overlap_ratio` (intersection ÷ *smaller* box's area, not plain IoU — robust to two duplicate boxes of different scale), keeps the highest-confidence box, tags survivor `MERGED` |
| 2 | Implausible size | geometric | `reject_geometric.geometric_reject_frame` stage 2, gated by `cfg.min_area_px2` / `max_area_px2` |
| 3 | Implausible shape | geometric | same function, stage 3, gated by `cfg.max_aspect_ratio` |
| 4 | Implausible displacement | temporal | `reject_temporal.reject_displacement` — walks each track's consecutive observed frames, breaks continuity past `cfg.max_speed_px_per_frame` |
| 5 | Unsupported detection | temporal | `reject_temporal.reject_unsupported` — drops tracks shorter than `cfg.min_track_len_supported` |
| 6 | Static detection | temporal | `reject_temporal.reject_static` — correlates box image-motion against VIO ego-motion (`vio_utils.VioSeries`) over a sliding window |

Order is enforced structurally, not by convention: `pipeline.run_pipeline`
calls `geometric_reject_frame` for every frame *before* `associate` even
exists as a concept, and `reject_temporal_all` takes `Track` objects that
`associate` produced — stages 4-6 are physically incapable of running
before tracks exist, matching the spec's own reasoning: "temporal rules
need tracks, which only exist after the association step."

### Why tracking (`association.py`) is here, even though it's not the FN part

Association is not false-negative recovery — it is required *by the FP
spec itself*. §3 is explicit that the per-frame instance cap must be
deferred past association and resolved by "ranking candidates by the track
supporting them rather than by their score in one frame" — a duplicate or
a bystander can outscore a real hand in a single frame, so a cap decision
has to be made from cross-frame track evidence, not per-frame confidence.
`selection.select_cap` is where that cap is actually enforced, ranking by
`(track_length, mean_confidence)`, and it structurally cannot run before
tracks exist — hence `association.py` sits upstream of it as required
infrastructure for a *false-positive* rule, not as false-negative work.
(It happens to also be reused by the optional interpolation extension
below — one tracker, two consumers.)

### Hand specialization of the FP rules (§5, §6)

| Property / edge case | Implementation |
| --- | --- |
| Cap of 2, request 3-4 candidates before selection | `config.hands_config()`: `class_max=2`, `candidate_pool_width` calibrated to 3 (see `REPORT.md`) |
| Head-mounted camera -> static rule unusually discriminating | `reject_temporal.reject_static` gates on VIO-measured camera motion (`vio_utils.VioSeries.is_camera_moving`), not just box stillness — a box only gets flagged static while the *camera* is confirmed moving |
| Second eye / stereo depth for arm's-reach (bystander rejection) | `stereo.py` — rectified epipolar template matching (`box_disparity`), wired into `reject_geometric.geometric_reject_frame` via the `reach_fn` hook, gated on `cfg.stereo_enabled` |
| Hands are equant -> shape rule is informative | `hands_config().max_aspect_ratio` calibrated tight (3.08) from stable-track statistics |
| Handedness unreliable when hands cross | `association.py` never reads `RawDetection.handedness` — matching cost is centroid distance + IoU only, so cap-selection ranking isn't corrupted by a flipped label |
| Duplicate boxes on one hand | `reject_geometric._merge_duplicates`, before cap selection |
| Hands cross or overlap, must not be treated as duplicate | Both retained by construction: `association.py` matches each track to its own motion-predicted position (Hungarian assignment), so two heavily-overlapping-but-distinct tracks don't collapse even at high IoU. Verified on the actual corpus: highest observed inter-track overlap is 0.91 IoU with both hands correctly retained as separate tracks |
| Another person's hands, position/entry alone insufficient | This is exactly the case stereo depth was meant to resolve. **Honest gap:** the stereo threshold could not be calibrated to a trustworthy value from this corpus's available weak labels (see `REPORT.md`) — `cfg.stereo_enabled=False` in the shipped config. The mechanism is implemented and wired through the pipeline; what's missing is a trustworthy number, not code. With it disabled, bystander rejection falls back on the track-support cap alone, which resolved 97.0% of all >=3-box frames corpus-wide in practice, but isn't the guaranteed per-frame separation the spec calls for |
| Gloved/occluded hand | Explicitly out of scope per the spec's own note ("needs labelled examples") — no special-cased handling added |

### Calibration (§7) and validation (§8)

Every threshold that gates an FP rule (`min_area_px2`, `max_area_px2`,
`max_aspect_ratio`, `max_speed_px_per_frame`, `candidate_pool_width`,
`duplicate_overlap_threshold`) was measured from the 39-clip corpus, not
picked by inspection — `adapter/calibrate.py` builds a permissive
"loose" track for every clip (dedup only, every other rule disabled),
filters to long/stable ones as a stand-in for "almost certainly a real
hand" (no ground truth exists in this corpus), and reads percentiles off
that population. `adapter/validate.py` reports precision/recall at each
FP-rejection-stage boundary and confirms recall drops monotonically as the
rules tighten, which is the direction §8 requires. Full numbers, including
the stereo threshold that failed calibration and why, are in `REPORT.md`.

## Beyond scope: false-negative recovery (§4)

Not required by the assignment, kept as a self-contained extension on top
of the FP work, using the same tracks `association.py` already builds:

- `interpolate.py` — extrapolates a track across a break and fills it with
  a straight-line-interpolated box only if the gap is short enough
  (calibrated from the corpus's own dropout-length distribution) and the
  track resumes near its predicted position.
- The leaving-the-frame test (`interpolate.is_leaving`) runs before every
  fill decision, so a hand that's actually exiting the frame — with a
  downward-exit bias for hands (`border_weights`, bottom weighted 1.6x vs
  top 0.6x) — is never fabricated back into existence.
- Validated two ways that need no ground truth: `validate.synthetic_dropout_eval`
  (hide a real span, re-interpolate, score against the withheld real
  boxes — IoU 0.98 at a 2-frame gap, degrading to 0.81 at the calibrated
  22-frame cutoff) and the corpus-wide interpolation-rate monitor (mean
  5.6%, one clip flagged as unusually high and explained in `REPORT.md`).

## Why no ML model was used

This is a deliberate choice, not an oversight, and it's grounded directly
in the spec rather than a general aversion to models: instruction.md
states plainly that the six FP classes are "separable without a model,"
and separately that the adapter "does not alter the detector or require
retraining." Layering a learned model onto a stage whose entire job is to
produce an auditable record of what changed and why (§2 — every correction
must be traceable, `reject_stage` + `source_ids` on every detection) would
work against the point of the stage: a rule's threshold can be read off a
percentile and defended in one sentence, a model's decision boundary
generally can't. Below are the places a model *would* plausibly help, and
why each one wasn't reached for here.

## Proposed extensions (not implemented) — where a model would and wouldn't help

**ByteTrack-style confidence-tiered association.** Plausible, targeted,
cheap. `association.py` currently treats every geometric survivor equally
in one matching pass; ByteTrack's core idea — match high-confidence boxes
first, then give unmatched tracks a second chance against the low-confidence
boxes the first pass ignored — maps directly onto the spec's own "motion
blur during rapid movement: confidence falls across several consecutive
frames" case. This would reduce avoidable track fragmentation during
low-confidence stretches. Estimated as an incremental recall improvement on
the false-negative side, not a change to the FP-rejection logic above.

**DeepSORT-style appearance re-ID, or a heavier long-term tracker (e.g.
DINOv3-based re-identification).** Considered and set aside for a
task-specific reason, not a general one: the hardest identity problem in
this corpus is telling the wearer's *own* left hand from their own right
hand when they cross — and appearance embeddings don't help there, because
both hands share the same skin, lighting, and camera; the spec's own
observation that "handedness is unreliable when hands cross" applies
equally to a learned visual classifier. Where appearance-based re-ID
usually earns its keep — recognizing an object again after a long
occlusion or re-entry — this corpus already has a stronger, cheaper signal
for the *harder* version of that problem (telling a bystander from the
wearer) in the form of stereo depth and VIO camera pose, which a monocular
appearance model would be approximating blind. Long-term re-ID architectures
built for monocular-only, no-pose, no-depth settings are solving the exact
absence this dataset doesn't have.

**XFeat+LightGlue (or similar sparse feature matching) for refining
interpolation.** This is the one place a learned model plausibly targets a
real, measured weakness on the false-negative side: `synthetic_dropout_eval`
shows interpolation quality degrading from IoU 0.98 at short gaps to 0.81 at
the longest calibrated gap, because straight-line motion is a worse
assumption the longer a real hand has to hold it. A feature-matching
refinement of the interpolated position could target that tail. That said,
XFeat+LightGlue specifically is built for *wide-baseline* matching (large
viewpoint/appearance change); a detector dropout here is the opposite — a
handful of frames at 30fps, small displacement, same camera — which is
classical optical flow's (Lucas-Kanade/KLT) problem shape, not a wide-baseline
matcher's, and would be far cheaper to run. Sparse local features are also
a poor match for hand patches specifically: low-texture skin, non-rigid
shape, and the exact frames worth bridging are disproportionately the
motion-blurred ones — precisely where local-feature matching degrades
hardest (the same constraint already forced a texture guard into
`stereo.py`'s disparity matcher). KLT-based refinement, tried first, would
be the natural next step before reaching for a heavier matcher.

## What's genuinely unresolved (not swept under the rug)

Measured, explained, and left as-is rather than forced — details and
numbers in `REPORT.md`:

1. Stereo arm's-reach threshold — disabled, weak label wasn't trustworthy
   (§3/§5's bystander case, the one FP class most affected).
2. A WiLoR foot-detected-as-hand false positive survives the adapter — out
   of scope for a post-processing stage: it's an object-identity error at
   the detector, not a tracking/temporal error this stage can see.
3. The static rule over-rejects on two sustained-low-hand-mobility desk
   tasks — a real edge case in the "camera is always moving enough to
   discriminate" assumption behind the static rule.
4. `reject_unsupported`'s reading of "no track before or after it" is one
   of two defensible interpretations of ambiguous spec wording; the
   alternative is documented rather than silently chosen.
